# Архитектура проекта

## Структура модулей

```
src/
├── main.rs
├── lib.rs
│
├── signal/          -- обработка сигналов
│   ├── mod.rs
│   ├── fft.rs       -- FFT, выделение 1x компоненты
│   ├── filter.rs    -- полосовой фильтр вокруг 1x
│   └── sync.rs      -- синхронное усреднение по keyphasor
│
├── sensor/          -- типы датчиков и поток данных
│   ├── mod.rs
│   ├── vibro.rs     -- виброметр: амплитуда + фаза
│   ├── xy_pair.rs   -- пара ортогональных виброметров (X/Y) -> вибровектор
│   ├── keyphasor.rs -- датчик фазы: RPM + опорный угол (опционален)
│   └── stream.rs    -- абстракция потока данных (ADC -> семплы)
│
├── balance/         -- алгоритмы балансировки
│   ├── mod.rs
│   ├── influence.rs -- метод коэффициентов влияния (1 и 2 плоскости)
│   ├── three_run.rs -- метод трёх пусков (без keyphasor, fallback)
│   ├── regime.rs    -- определение режима (до/резонанс/за) + коррекция фазы
│   └── rpm.rs       -- определение RPM из спектра (без keyphasor)
│
├── rotor/           -- модель ротора
│   ├── mod.rs
│   ├── geometry.rs  -- плоскости коррекции, позиции датчиков
│   └── weight.rs    -- расчёт массы и угла корректирующего груза
│
├── math/            -- базовая математика
│   ├── mod.rs
│   ├── complex.rs   -- комплексная арифметика (вибровектор = амплитуда*angle*фаза)
│   └── linalg.rs    -- решение 2x2 систем для двухплоскостной балансировки
│
└── types.rs         -- newtype'ы
```

## Ключевые типы

```rust
// --- Newtype indices (по CLAUDE.md) ---
struct PlaneId(pub usize);     // плоскость коррекции (0 или 1)
struct SensorId(pub usize);    // датчик вибрации

// --- Вибровектор ---
// Центральный тип. Амплитуда + фаза = комплексное число в полярной форме.
struct VibroVector {
    amplitude: f64,  // мкм, мм/с, или м/с^2
    phase: f64,      // радианы, относительно keyphasor
}
// Поддерживает: сложение, вычитание, деление, умножение на скаляр.
// Внутри хранится полярная форма, для арифметики конвертируется в декартову.

// --- Пробный/корректирующий груз ---
struct Weight {
    mass: f64,       // граммы
    angle: f64,      // радианы, позиция на роторе
    plane: PlaneId,
}

// --- Коэффициент влияния ---
// Комплексное число: "сколько вибрации (на датчике) создаёт единичный груз (в плоскости)"
struct InfluenceCoeff {
    value: Complex64,  // (мкм/г) или (мм/с/г)
}

// --- Результат балансировки ---
struct Correction {
    plane: PlaneId,
    mass: f64,        // граммы
    angle: f64,       // радианы
}

// --- Данные с датчиков ---
struct Sample {
    value: f64,       // напряжение ADC -> физ. величина
    timestamp_us: u64,
}

struct KeyphasorEvent {
    timestamp_us: u64,  // момент прохождения метки
}
```

## Поток данных

### Путь A: с X/Y парой (основной, без keyphasor)

```
ADC (X вибро)  --+
                  +--> [sensor::xy_pair] --> VibroVector (амплитуда, фаза)
ADC (Y вибро)  --+                                |
                                                   |
                      [signal::fft] --> RPM из спектра
                                                   |
                      [balance::influence] --> Correction (масса, угол, плоскость)
```

### Путь B: с keyphasor (классический)

```
ADC (виброметры)  ----> [signal::stream] ----> сырые семплы
                                                    |
Keyphasor         ----> [sensor::keyphasor] --> RPM + фазовая метка
                                                    |
                            +--- [signal::sync] --- синхронное усреднение
                            |        или
                            +--- [signal::fft] ---- FFT + выделение 1x
                                                    |
                                              VibroVector (амплитуда, фаза)
                                                    |
                            [balance::influence] -- коэфф. влияния + коррекция
                                                    |
                                              Correction (масса, угол, плоскость)
```

### Путь C: только амплитуды (fallback, без keyphasor, без X/Y)

```
ADC (виброметры)  ----> [signal::fft] ----> амплитуда 1x (скаляр)
                                                    |
                            [balance::three_run] -- метод трёх пусков
                                                    |
                                              Correction (масса, угол, плоскость)
```

## Зависимости (crates)

- `rustfft` — FFT (no_std-совместимый при необходимости)
- `num-complex` — Complex64 для вибровекторов
- `libm` — математика для embedded (sin, cos, atan2, sqrt)

Для тестов/симуляции:
- `rand` — генерация шума для тестовых сигналов

## Порядок реализации

### Фаза 1: ядро (минимальная рабочая балансировка)
1. `types.rs` — newtype'ы и базовые структуры
2. `math/complex.rs` — VibroVector и операции
3. `math/linalg.rs` — решение 2x2 системы
4. `balance/influence.rs` — одноплоскостной метод
5. `balance/influence.rs` — расширение до двухплоскостного

### Фаза 2: обработка сигнала
6. `signal/fft.rs` — FFT, выделение 1x из сырого сигнала
7. `sensor/xy_pair.rs` — восстановление вибровектора из X/Y пары
8. `balance/rpm.rs` — определение RPM из спектра

### Фаза 3: расширения
9. `signal/sync.rs` — синхронное усреднение (для пути с keyphasor)
10. `balance/three_run.rs` — метод без keyphasor и без X/Y (fallback)
11. `balance/regime.rs` — определение режима и коррекция фазы
12. `rotor/` — геометрия и визуализация результата
