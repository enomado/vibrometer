# Проектные решения

Принятые решения по архитектуре и подходам.

## Keyphasor: обязателен

Keyphasor (физическая привязка к ротору) — **обязательный** компонент.

**Почему**: без абсолютной фазовой привязки к ротору невозможна итеративная
балансировка. X/Y пара даёт относительную фазу (в координатах корпуса),
но "ноль" плывёт между пусками. Если первая коррекция не попала — 
нет стабильной системы координат для вычисления следующей.

С keyphasor каждый пуск даёт вибровектор в одной системе координат ротора →
можно итерировать: поставил груз → измерил → не хватает → добавил/сдвинул.

Текущий рабочий pipeline в receiver:
- RPM и фаза 1x берутся по keyphasor, если в блоке хватает фронтов
- При наличии keyphasor 1x вычисляется через Goertzel на измеренном RPM
- Запись можно вести непрерывно или по фиксированному числу оборотов
- Поиск RPM из спектра остаётся fallback, когда keyphasor в блоке нет

Варианты реализации keyphasor:
- **Индуктивный** — паз/шпонка на валу (работает через масло и грязь)
- **Hall-датчик** — магнит на валу
- **Оптический** — отражающая метка + фотодатчик
- **Encoder** — на торце вала

**X/Y пара** остаётся как дополнительный источник данных (полная картина 
эллипса вибрации, диагностика), но не как замена keyphasor.

## RPM: keyphasor сначала, спектр как fallback

При наличии keyphasor RPM определяется по периоду между фронтами.
Если keyphasor нет или фронтов недостаточно, используется FFT спектр вибрации:
доминирующий пик в ожидаемом диапазоне = частота вращения.

## Качество сигнала: полный waveform

Выбран уровень 3 (полный сигнал с ADC, 10-50 кГц).

**Почему**:
- Из полного сигнала программно получаются уровни 1 и 2
- FFT фильтрует 1x от шума без аналогового фильтра
- Диагностика (2x, 3x) — бонус
- STM32 с DMA это тянет

## ESP32-C3 coex: сначала ISR по DRDY, потом DMA

Для текущего железа (`ESP32-C3` + `ADS1256` + WiFi/BLE coexistence) первым
рабочим решением оказался не DMA сам по себе, а перенос захвата сэмпла на
GPIO ISR по `DRDY↓`.

**Почему**:
- при `embassy` + WiFi/BLE на single-core C3 терялись не байты в SPI, а сами
  события `DRDY`, если edge происходил между `wait_for_falling_edge()` и
  следующим ожиданием
- blocking `SPI RDATA` внутри ISR Priority2 оказался устойчивее, чем
  async-задача с blocking SPI вне ISR
- DMA остаётся желательной оптимизацией, но уже как следующий шаг:
  уменьшить длительность ISR и занятость SPI, а не как базовый механизм
  исправления потерь семплов

Практический вывод: если на C3 при 7500 SPS снова появляются дропы под coex,
сначала проверять путь захвата `DRDY` и приоритеты ISR, а уже потом
экспериментировать с DMA.

## Режим измерения: фиксированные обороты

Основной режим — фиксированные рабочие обороты.
Прогон (Bode plot) — опциональный, для первичной настройки.

**Почему**: для серийной балансировки однотипных роторов прогон избыточен.
Достаточно один раз определить критическую скорость и режим работы.

## Метод трёх пусков и две плоскости

Метод трёх пусков в классическом виде — одноплоскостной.
Для двух плоскостей без фазы нужно 7 пусков (3+3+начальный)
с нелинейной математикой (пересечение окружностей).

Это fallback, основной путь — X/Y пара с линейной математикой.

## Конфигурации датчиков

| Конфигурация | Датчики | Пусков (2 плоскости) | Метод |
|---|---|---|---|
| A: keyphasor (**основная**) | 2 вибро + keyphasor | 3 | Influence coefficient |
| B: keyphasor + X/Y | 4 вибро + keyphasor | 3 | Influence coefficient + диагностика |
| C: без keyphasor (fallback) | 2 вибро | 7 | Три пуска (нелинейный, одноразовый) |
